# 游园会专属小游戏契约

「专属小游戏」是游园会游戏摊位中的一个稳定模板，对外始终使用 `templateId: "custom"`。模板内部再通过稳定的 `seriesId` 选择包装和题目骨架。它复用当前游园会的真实双端房间、独立邀请卡和服务端状态，不使用旧 Demo 的 A/B 视角切换来模拟另一位用户。

本文档的数据边界仅适用于 `/carnival` 游园会的 `custom` 模板。默认 Demo 另有完整匹配资料，其 AI 链路可以使用从 `profile`、双方记忆和择偶偏好中提炼的 allowlist 非敏感信号，但不发送原始私密文本。游园会注册只收集昵称和性别，因此本文档下述生成内容只来自当前房间的公开聊天安全线索。

## 稳定标识

| `templateId` | `seriesId` | 展示名 | 运行机制 |
| --- | --- | --- | --- |
| `custom` | `courtside` | 默契篮球 · 双人攻防 | 选主场、暂停暗号、绝杀配合 |
| `custom` | `chat-archaeology` | 聊天考古队 · 挖出未完待续 | 话题碎片、想继续的支线、一句话注释 |
| `custom` | `weekend-studio` | 周末制片厂 · 合拍一支短片 | 开场镜头、节奏选择、彩蛋结尾 |
| `custom` | `contrast-lab` | 反差实验室 · 解锁另一面 | 充电方式、临时起意、小小偏爱 |
| `custom` | `future-trailer` | 未来预告片 · 下一集会怎样 | 下一集、同框一天、片尾彩蛋 |
| `custom` | `prompt-arcade` | AI 游戏工坊 · 说一句就开局 | 完整 HTML/CSS/JavaScript + 连续双人操作 |

`templateId` 和 `seriesId` 是持久化、幂等与路由字段，不得使用可编辑的中文展示名代替。改名时不变更这两个标识。

## 内容来源与安全边界

游园会专属小游戏只能使用当前房间中双方已经发送的公开文字聊天。用户昵称仅用于界面展示，性别仅用于异性匹配；两者都不作为题目推断依据。

不读取、提炼或发送下列信息：

- Demo 中才存在的 `profile`、`memories_self`、`memories_ideal` 和择偶偏好；
- 性别、收入、健康、住址、联系方式等敏感或可识别信息；
- 从单句聊天推断的人格、依恋类型、经济状况或关系结论。

生成上下文先在服务端清洗公开聊天：最多保留最近 60 条截断后的文字消息，并剔除含联系方式或链接的消息；Prompt 预览与本地推荐只展示安全话题标签和消息数量。任何题面仍要经过敏感主题与联系方式二次校验。聊天线索不足时，界面必须标记「通用暖场」，不得伪称某内容来自双方聊天。

## 选择、Prompt 与邀请

1. 房间双方累计完成 10 条文字消息后，`custom` 与其他游戏模板同时解锁。
2. 用户进入「专属小游戏」后，可查看系统推荐的 `seriesId` 及基于公开聊天安全线索的简短原因，也可主动改选任一系列。
3. 前端获取包含 `templateId: "custom"` 和所选 `seriesId` 的 Prompt 草稿。用户可修改该 Prompt；字数、联系方式与链接限制由服务端重新校验，硬安全规则不可被覆盖。
4. 前端调用 `POST /api/carnival/game-preview`，服务端生成一份 5 分钟有效的可玩预览并返回 opaque `previewToken`。`prompt-arcade` 会先核对 artifact 指纹，再在无同源权限的 iframe 中运行整局代码；试玩不修改正式房间状态。
5. 修改 Prompt 或改选系列会立即作废当前预览。满意后创建邀请时提交同一个 `previewToken` 和 `Idempotency-Key`，服务端原样复用已试玩的游戏，不再二次生成。
6. `previewToken` 绑定发起人、房间、公开聊天版本、`seriesId`、Prompt 哈希和精确游戏定义；伪造、跨用户、改 Prompt、改系列、过期或公开聊天变化都会被拒绝。
7. 服务端为每次创建生成全局唯一的 `inviteId`，将已确定的 `seriesId`、游戏定义和状态原子持久化。双方可同时发起不同邀请，后发邀请不覆盖先发邀请。
8. 点击聊天时间线中的某张卡片时，所有加入、作答、猜测和刷新请求都必须继续携带该卡片的 `inviteId`，不得按「当前最新游戏」路由。

最小创建请求语义如下：

```json
{
  "templateId": "custom",
  "seriesId": "prompt-arcade",
  "prompt": "做一个篮球攻防游戏：一人投篮，一人左右移动篮筐防守……",
  "previewToken": "服务端返回的_opaque_版本令牌"
}
```

`seriesId` 必须属于上述稳定集合，不允许由 Prompt 临时创造新标识。

## 真实双端状态流程

`courtside` 等 5 个旧系列继续使用稳定的三轮 `answer / guess / next` 协议。`prompt-arcade` 使用 `arcade.ready / arcade.input / arcade.tick`：生成代码只发送白名单操作，角色、物理、倒计时、操作序列、比分和胜负都由服务端权威状态决定。

1. 发起人创建邀请后已加入本局；另一方点击该 `inviteId` 的卡片后加入。
2. 旧系列每轮指定 `answerer` 和 `guesser`，揭晓前不投影对方答案；揭晓后给出中性追问。
3. `prompt-arcade` 加入时由服务端分配双方角色和允许操作；客户端每个动作携带单调序号、requestId 与 expectedRevision。
4. 生成页面发出的 `game.complete` 只是非可信动画提示，不能结束正式房间或写入比分；只有服务端状态进入 `finished` 才算完成。
5. 「放进聊天输入框」只回填当前用户草稿，不自动发送。
6. 页面关闭或刷新后，应通过原 `inviteId` 恢复题目或街机状态、双方角色、事件游标与公开结果。

## AI 生成与本地回退

除 `prompt-arcade` 外，5 个旧系列使用 `exclusive-choice-v1` 声明式协议，只允许 `card-grid`、`swipe-deck`、`mood-dial` 和 `orbit-pick` 四类本地渲染器，并保持三轮答猜与隐私规则。

`prompt-arcade` 使用 schema v4 / `arcade-v1`。模型可以输出一份完整、自包含的 HTML/CSS/JavaScript document，但必须通过严格 schema、大小、单脚本、能力与敏感内容校验；不允许网络、外部 URL、存储、设备权限、父页 DOM、动态代码或自定义服务端规则。服务端为唯一脚本计算精确 CSP hash，运行端再核对 artifact SHA-256 后才挂载 `sandbox="allow-scripts"` iframe。旧 schema v2/v3 邀请仍可恢复并使用原渲染器。

遇到未配置、超时、鉴权失败、限流、结构错误或安全校验不通过时：

- 保留用户选择的 `seriesId`；
- 使用该系列自己的本地安全题卡或小游戏代码，不降级成其他系列；`prompt-arcade` 会通过本地编译器选择对抗、合作、运动、冒险或策略引擎，并生成可实际操作的安全 fallback；
- 题卡可以使用已清洗的公开话题标签；线索不足时使用标记为「通用暖场」的系列默认题；
- 仍然创建独立 `inviteId` 并走完相同的双端保密、揭晓与刷新恢复流程；
- 在邀请中标记为本地回退，但不向浏览器暴露上游错误原文、Key 或管理配置。

## 系列适配规则

- `courtside`：适合聊天中已有运动、互动感或活泼语气的房间；没有相关线索时不自动列为首推。
- `chat-archaeology`：适合文字消息较多、已出现多个双方参与话题的房间；不复述敏感原句。
- `weekend-studio`：适合已有共同休闲兴趣的房间；所有情境可拒绝、可调整，不默认线下见面。
- `contrast-lab`：只在公开聊天中有足够日常偏好表达时推荐；用「发现新线索」而不是人格分析。
- `future-trailer`：只在双方都持续参与且最近没有结束信号时推荐；只往前想一小步，不生成关系定义、承诺或施压式邀约。
- `prompt-arcade`：用户主动描述想玩的主题和手感；AI 可生成完整页面代码，但只能运行在受限沙箱并通过 PairPlay v1 发送允许的操作，正式状态始终由服务端控制。

## 最小验收标准

- 两个独立浏览器会话可在同一 `inviteId` 中完成旧系列三轮或一局连续操作的 `prompt-arcade`，不需要切换本地视角。
- 两人同时发起不同 `seriesId` 时，两张邀请都存在，点击后进入各自的题目快照。
- 任一轮揭晓前，无论状态轮询、刷新或接口重试，都无法从另一方的响应中获得私密答案。
- 修改后的 Prompt 会改变可试玩的游戏代码、场景与玩法，但不能更换 `seriesId`、突破 schema 或覆盖服务端权威规则。
- 用户发出的邀请必须与其最后试玩的精确版本一致，创建重试不得二次调用 AI 或生成另一份题面。
- AI 不可用时，六个系列都有可完整玩的对应本地回退；`prompt-arcade` 仍会得到真实可操作的本地街机玩法。
- 刷新任意一端后可从原 `inviteId` 恢复，已揭晓轮次不重复、未揭晓答案不泄露。
- 320 px 宽度下可完成选系列、编辑 Prompt、沙箱试玩、连续双人操作和回填聊天全流程。
